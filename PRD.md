# PRD.md — Product Requirements Document
> Project: KOMS | Generated by scaffold-prd on 2026-07-12
> Source: BRD.md (revised — v1 scoped to Gio's own classes, no owner buy-in yet)

---

## Product Vision
KOMS is a solo-built PWA giving Gio one unified place to run his own robotics/coding classes — attendance, video documentation, and credit-based progress reporting — replacing OClass, Excel, and manual Telegram/WhatsApp relay, as a working pilot toward eventual academy-wide adoption.

---

## Visual Design Direction
**Aesthetic:** Modern, sleek, tech. Dark mode base with a data-stream motif — particles/lines suggesting live data flow (not literal rain, but that visual energy).
**Color palette:** Blue-green as the primary tech color; maroon/red and blue as secondary accents.
**Responsive:** Desktop, tablet, and mobile — not mobile-only, despite PWA-first framing.
**Confirmed stack:** Next.js, Tailwind (latest), Framer Motion (for the journey path animations especially), shadcn/ui, Supabase (auth + database), Google Drive (video storage).
**High-fidelity execution:** Wireframes done (this doc's Screen Inventory + earlier low-fi wireframes). Actual pixel design happens in Claude Design, not here — this section is the brief it works from.

---

## User Personas
See BRD.md. V1 has two active user types: **Gio, as Teacher** (full read/write on his own classes), and **Parents** (read-only access to their own linked child). Center Manager and Owner/Admin roles exist in the schema (RLS-ready, per the TCS Coffee pattern) but have no screens in v1.

## Screen Inventory

### Login
**Route:** `/login`
**Persona(s):** Teacher
**Purpose:** Authenticate Gio into KOMS
**Triggered by:** App opened while logged out
**Data displayed:** none (pre-auth)
**User actions:**
  - Submit email + password → leads to: Dashboard (success) | inline error (failure)
**Edge cases:**
  - Wrong credentials → inline error, no redirect
  - Network failure → retry message, not a blank screen
**Priority:** P0

### Dashboard / My Classes
**Route:** `/dashboard`
**Persona(s):** Teacher
**Purpose:** See all classes Gio teaches and jump into today's session
**Triggered by:** Successful login
**Data displayed:**
  - List of classes — source: `classes` (filtered by `teacher_id`)
  - Today's scheduled session (if any) — source: `sessions`
**User actions:**
  - Tap a class → leads to: Class Roster
  - Tap "Log Today's Session" → leads to: Log Session
**Edge cases:**
  - No classes assigned yet → empty state: "No classes yet — add one to get started" + link to Add Class
**Priority:** P0

### My Schedule
**Route:** `/schedule`
**Persona(s):** Teacher
**Purpose:** Calendar view of Gio's own upcoming and past sessions — scoped to his classes only, not academy-wide
**Triggered by:** Nav tab from Dashboard
**Data displayed:**
  - Scheduled/completed sessions — source: `sessions` (filtered by `teacher_id`)
**User actions:**
  - Tap "Add Session" → creates a new scheduled session (class, date, time) → saves to: `sessions` with status `scheduled`
  - Tap a past date's session → leads to: Log Session (if not yet logged) or Student/session detail (if already logged)
**Edge cases:**
  - No sessions scheduled yet → empty state with "Schedule your first session" CTA
**Priority:** P0

### Manage Teachers (Admin)
**Route:** `/admin/teachers`
**Persona(s):** Admin (Gio)
**Purpose:** Add teacher records so classes/sessions can be assigned to them — the foundation for a full academy calendar
**Triggered by:** Nav item, admin-only
**Data displayed:**
  - Existing teacher records — source: `users` where `role = 'teacher'`
**User actions:**
  - Add teacher (name, email) → creates `users` row with role `teacher` → saves to: `users`
  - Invite sent via magic link (same mechanism as parent invite) — doesn't mean the teacher is actively using it, just that the record exists
**Edge cases:**
  - No teachers added yet beyond Gio → empty state, not an error
**Priority:** P0

### Academy Schedule (Admin)
**Route:** `/admin/schedule`
**Persona(s):** Admin (Gio)
**Purpose:** Full calendar across every teacher and class — the demo-ready view of the whole vision
**Triggered by:** Nav item, admin-only
**Data displayed:**
  - All sessions across the center, any teacher — source: `sessions` (center-wide, not filtered by teacher_id)
**User actions:**
  - Assign any teacher to any class/session → saves to: `sessions.teacher_id`
  - Create/edit/delete any session regardless of who's assigned
**Edge cases:**
  - Only Gio exists as a teacher so far → schedule just shows his sessions until more teacher records are added; this is expected, not broken
**Priority:** P0

### Manage Lesson Plan (Admin)
**Route:** `/admin/classes/:classId/lessons`
**Persona(s):** Admin (Gio)
**Purpose:** Author the curriculum template — the ordered lesson list every student's journey path is generated from
**Triggered by:** Nav item from a class, admin-only
**Data displayed:**
  - Existing lessons for this class, in order — source: `lessons`
**User actions:**
  - Add lesson (title, description) → appended at next `sequence_number` → saves to: `lessons`
  - Reorder lessons → updates `sequence_number`
  - Edit/delete a lesson
**Edge cases:**
  - Deleting a lesson that students have already completed → warn clearly, don't silently orphan `student_lesson_progress` rows
**Priority:** P0

**Note on Center Switcher:** not a separate screen — a persistent dropdown in the admin layout header, present on every `/admin/*` route. Only one option in v1 (Gio's center), but every admin query is scoped through it from day one.

### Class Roster
**Route:** `/classes/:classId`
**Persona(s):** Teacher
**Purpose:** See all students in a class and their current lesson progress at a glance
**Triggered by:** Tapping a class from Dashboard
**Data displayed:**
  - Students — source: `enrollments` joined `students`
  - Each student's lesson progress (X/Y completed) — source: `student_lesson_progress`, `lessons`
**User actions:**
  - Tap a student → leads to: Student Detail
  - Tap "Add Student" → leads to: Add/Edit Student
  - Tap "Log Session" → leads to: Log Session (pre-filled for this class)
**Edge cases:**
  - No students enrolled → empty state with "Add Student" CTA
**Priority:** P0

### Log Session
**Route:** `/classes/:classId/sessions/new`
**Persona(s):** Teacher
**Purpose:** Record everything about one class session in a single flow — attendance, video, notes, lesson completion
**Triggered by:** "Log Session" from Dashboard or Class Roster
**Data displayed:**
  - Roster for this class — source: `enrollments`
  - Video upload state — source: `session_videos`
**User actions:**
  - Mark each student present/absent → saves to: `attendance`
  - Upload video (Google Drive picker or link paste) → saves to: `session_videos`
  - Write per-student or session notes → saves to: `sessions.notes` / per-student note field
  - Mark lesson(s) complete per student (from that class's lesson plan) → saves to: `student_lesson_progress`
  - Submit → leads to: Dashboard, with confirmation
**Edge cases:**
  - Video upload fails → session still saves without video; video can be added later, not a blocker
  - No students marked → warn before allowing submit ("No attendance marked — continue anyway?")
  - Network drops mid-entry → local draft retained, not lost on refresh
**Priority:** P0

### Student Detail / Credit History
**Route:** `/students/:studentId`
**Persona(s):** Teacher
**Purpose:** One trustworthy record for a student — the screen that ends parent disputes
**Triggered by:** Tapping a student from Class Roster
**Data displayed:**
  - Full attendance history — source: `attendance`
  - Full lesson progress history with dates — source: `student_lesson_progress` joined `lessons`
  - Linked session videos — source: `session_videos`
  - Session notes over time — source: `sessions`
**User actions:**
  - Tap "Generate Report" → leads to: Generate Report
  - Tap a past session → leads to: session detail (read-only)
**Edge cases:**
  - Brand-new student, no history yet → empty state: "No sessions logged yet"
**Priority:** P0

### Generate Report
**Route:** `/students/:studentId/report`
**Persona(s):** Teacher
**Purpose:** Turn rough session notes + lesson progress data into a polished, exportable PDF report
**Triggered by:** "Generate Report" from Student Detail
**Data displayed:**
  - Pulled lesson progress + attendance summary — source: `student_lesson_progress`, `lessons`, `attendance`
  - Gio's rough notes — source: `sessions.notes`
  - AI-drafted report text (after generation) — source: Claude API response, held in local/edit state
**User actions:**
  - Tap "Draft with AI" → calls Claude API → populates editable text field
  - Edit drafted text → local state
  - Tap "Export PDF" → renders fixed template with final text → saves to: `reports` → immediately visible on the student's Student Profile
**Edge cases:**
  - AI draft fails/times out → show error, allow manual text entry as fallback (never block report creation on AI availability)
  - No lesson progress/attendance data yet → warn before drafting ("Limited data — report may be sparse")
**Priority:** P0

### Add/Edit Student
**Route:** `/classes/:classId/students/new` (and `/students/:studentId/edit`)
**Persona(s):** Teacher
**Purpose:** Manually add a student since there's no OClass data sync
**Triggered by:** "Add Student" from Class Roster
**Data displayed:** existing student data (edit mode only)
**User actions:**
  - Submit name + parent contact → saves to: `students`, `enrollments`
**Edge cases:**
  - Duplicate name → allow it, don't block (real families do have repeat surnames), rely on internal ID not name-matching
**Priority:** P0

### Add/Edit Class
**Route:** `/classes/new`
**Persona(s):** Teacher
**Purpose:** Define a class. The lesson plan itself is authored separately in Manage Lesson Plan (Admin).
**Triggered by:** "Add Class" from Dashboard
**Data displayed:** existing class data (edit mode)
**User actions:**
  - Submit name, age bracket → saves to: `classes`
**Edge cases:** none beyond standard validation
**Priority:** P1 — can be seeded directly in the DB for July 31 if time is tight; UI can follow

### Student/Parent Login
**Route:** `/student/login`
**Persona(s):** Parent/Student
**Purpose:** Passwordless entry — parent enters email, gets a magic link
**Triggered by:** Invite link, or returning to KOMS later
**Data displayed:** none (pre-auth)
**User actions:**
  - Submit email → receives magic link → leads to: Student Profile (auto if one child, student switcher if multiple)
**Edge cases:**
  - Email not linked to any student → clear message, not a silent failure ("No student found for this email — check with your child's teacher")
**Priority:** P0

### Student Profile (parent/student view)
**Route:** `/student/:studentId` (auto-redirects here from login if only one linked child)
**Persona(s):** Parent/Student
**Purpose:** The hub — replaces the old flat "Student Progress Page." One trustworthy view of who this student is and what they're enrolled in, with the journey one tap away
**Triggered by:** Successful magic-link login (auto if one child) or student switcher (if multiple)
**Data displayed:**
  - Avatar, name — source: `students`
  - Active program cards — source: `enrollments` joined `classes`, where the student has incomplete lessons
  - Completed program cards — source: `enrollments` joined `classes`, where all lessons for that class are completed
  - Reports list — source: `reports`
**User actions:**
  - Tap a program card → leads to: Journey (for that class)
  - Tap a report → opens/downloads the PDF
  - If multiple children linked, switch student → reloads this screen for the other child
**Edge cases:**
  - No programs enrolled yet → empty state, not blank ("Not enrolled in a program yet")
  - RLS must guarantee this parent can query ONLY their own linked student — enforced at the database level, not just hidden in the UI
**Priority:** P0

### Journey (snake-path lesson progress)
**Route:** `/student/:studentId/classes/:classId/journey`
**Persona(s):** Parent/Student, Teacher (same view, teacher gets it read/write via Log Session instead)
**Purpose:** Visualize the curriculum as a winding path of lesson nodes — locked, completed, and current — instead of a number in a spreadsheet
**Triggered by:** Tapping a program card on Student Profile
**Data displayed:**
  - Ordered lesson nodes — source: `lessons` (by `sequence_number`)
  - Per-node status — source: `student_lesson_progress`
**User actions:**
  - Tap a completed node → shows date completed, linked session video, teacher notes for that lesson
**Edge cases:**
  - Class has no lesson plan defined yet (admin hasn't built it) → empty state directing back, not a broken path render
**Priority:** P0

## User Actions Note
The parent/student side is strictly read-only in v1. No editing, no messaging back, no account settings beyond login — keeps the security surface small while still solving the actual problem (parents currently have zero independent visibility).

## User Stories (P0 + P1)

**As Gio (Teacher), I want to log attendance and upload a session video in one screen, so that I never have to touch Telegram or a separate attendance app again.**
Acceptance criteria:
- [ ] Every student in the class roster appears with a present/absent toggle, defaulting to unmarked
- [ ] Video can be attached via Google Drive picker or by pasting a Drive link
- [ ] Submitting with 0 students marked shows a confirmation warning, not a silent save
- [ ] On success, redirect to Dashboard with a visible confirmation toast
- [ ] If video upload fails, the rest of the session still saves successfully

**As Gio (Teacher), I want to mark lessons complete per student per session, so that progress lives in one system instead of a separate Excel file.**
Acceptance criteria:
- [ ] Lessons from that class's lesson plan can be marked complete per student within the Log Session flow
- [ ] Completion entries are timestamped and tied to the specific session
- [ ] A student's journey (Journey view) updates immediately and is visible on their Student Detail screen

**As Gio (Teacher), I want a single record per student showing attendance, lesson progress, and videos, so that I can resolve a parent dispute by opening one screen instead of cross-checking three tools.**
Acceptance criteria:
- [ ] Student Detail shows attendance history, lesson progress history, and linked videos on one screen
- [ ] Each entry shows a date, so timeline order is unambiguous
- [ ] Empty state shown clearly if a student has no history yet, not a blank/broken screen

**As Gio (Teacher), I want AI to draft the report text from my rough notes, so that I don't have to hand-write a polished report for every student.**
Acceptance criteria:
- [ ] "Draft with AI" pulls the student's lesson progress/attendance summary plus Gio's rough notes into the prompt
- [ ] Drafted text appears in an editable field — never auto-exports without review
- [ ] If the AI call fails, Gio can still type the report manually and export
- [ ] Exported PDF uses the fixed template designed via Claude Design

**As Gio (Admin), I want to define an ordered lesson plan for a class, so that every enrolled student's journey path is generated from one real curriculum instead of an arbitrary credit number.**
Acceptance criteria:
- [ ] Lessons can be added, reordered, and edited for a class
- [ ] Deleting a lesson that students have already completed shows a clear warning first
- [ ] Every student enrolled in that class automatically gets a journey path reflecting the current lesson plan

**As a Parent/Student, I want to log in and see progress directly on a profile with a visual journey, so that I don't have to wait on someone manually forwarding updates, and I can independently verify attendance/progress records if there's ever a dispute.**
Acceptance criteria:
- [ ] Can log in with just an email via magic link — no password to manage
- [ ] Login only works for emails linked to an enrolled student
- [ ] Student Profile shows active/completed program cards, and each links to a snake-path Journey view
- [ ] A parent/student can never retrieve another family's student data, under any input — enforced by database-level RLS, not just UI hiding

## Out of Scope (V1)
The following are explicitly excluded from the current build — Claude Code must not build these without new instruction:

- [ ] Academy-wide scheduling/booking (all teachers/centers) — deferred to V2, requires owner buy-in. A scoped-down calendar for Gio's own classes IS in V1 (see Scheduling epic).
- [ ] Payments/invoicing — stays on OClass indefinitely, not part of KOMS's remit
- [ ] CRM/lead management — stays on OClass
- [ ] Automated WhatsApp Business API push — requires owner-sponsored business verification; parent portal login covers the actual need instead
- [ ] Parent account self-editing (name/email changes, notification preferences) — v1 parent side is read-only, login only
- [ ] Self-service report template editor UI — Gio edits the template directly as builder
- [ ] Center Manager screens — role exists in schema (RLS-ready) but no UI; Admin screens (Manage Teachers, Academy Schedule) ARE in v1, used by Gio
- [ ] Other teachers actually operating inside KOMS day-to-day — records can exist (Manage Teachers), but real onboarding/usage by other staff is gated on the business owner
- [ ] Multi-center data entry UI — schema supports it, but only one center is seeded for v1
- [ ] OClass data migration/sync — Gio doesn't have admin access to OClass as a non-owner; flagged as an open question, not assumed solvable

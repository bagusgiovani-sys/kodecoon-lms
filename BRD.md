## Product Summary
**Name:** KOMS
**One-liner:** Internal operations system for Kodecoon Academy Indonesia that unifies class scheduling, session attendance, video documentation, and AI-assisted credit-based progress reporting into one source of truth.
**Type:** PWA (installable web app — no app store)
**Owner:** Kodecoon Academy Indonesia (internal tool, not resold to other academies)
**Team:** Solo — Gio, building with Claude Code (mid/senior on architecture, junior on raw syntax)

---

## Business Objectives
**Why this exists:** Kodecoon currently spreads scheduling, attendance, and credit tracking across OClass (a generic Singapore SaaS for dance/gym/tuition studios), a separate Excel sheet, and a manual Telegram→WhatsApp video relay chain done by hand. None of these agree with each other, so when a parent disputes an absence or a credit deduction, staff can't produce one trustworthy record — there is no single source of truth. Session video documentation for robotics classes depends entirely on a teacher remembering to upload to Telegram and a manager remembering to forward it to parents.

**Success at launch (v1, revised):** Every one of Gio's own class sessions is marked present/absent, has its video uploaded, and has credit progress logged — inside KOMS, with zero reliance on OClass, Excel, or manual Telegram/WhatsApp relay for those actions. Org-wide rollout (other teachers, other centers) is a v2 goal contingent on owner buy-in, not a v1 launch requirement.

**Key metrics** *(inferred — flag if wrong):*
1. % of sessions fully logged in KOMS vs. old tools
2. Time from "class ends" to "parent has the video"
3. Zero data conflicts between attendance/credit records when a parent disputes something

**Failure condition** *(inferred — flag if wrong):* Staff quietly reverts to Excel/Telegram/OClass because KOMS is slower or missing something they relied on.

## Adoption Path
**Reality:** Gio is building KOMS on his own initiative, as a mentor with technical skills solving his own daily pain. Kodecoon's owner is NOT currently aware of this project. There is no organizational mandate.

**What this means for scope:**
- V1 must be fully usable by Gio alone, on his own classes, without requiring any other teacher, center manager, or the owner to participate or approve anything.
- Org-wide infrastructure (replacing the academy's shared scheduling system, rolling out to other teachers/centers) is NOT v1-appropriate — Gio doesn't have the authority or organizational reach to mandate that alone.
- Video/attendance data involves minors (students). Keeping the pilot scoped to Gio's own classes, rather than pulling in other teachers' student data without sanction, is a deliberate risk boundary, not a technical limitation.
- **Plan:** Build and prove the pilot solo → demonstrate working system to the owner/center managers → expand org-wide (including scheduling replacement) only after buy-in.

## Reference & Differentiation
**Similar to:** OClass — a generic Singapore class-management SaaS (CRM, scheduling, payments, attendance) built for dance studios/gyms/tuition centers, not for a credit-based robotics/coding curriculum.
**Better than OClass at:** One unified session record (schedule + attendance + video + credit in one place) instead of three disconnected tools that disagree with each other; automated parent notification instead of manual relay; AI-assisted report drafting instead of manual spreadsheet compilation.
**Deliberately NOT doing (v1):** Payments/invoicing, CRM/lead management, automated WhatsApp Business API push (parent portal login replaces the need for it) — *confirmed with Gio, parent portal moved IN scope for v1.*

## Phased Scope
**Revised after confirming no owner buy-in exists (see Adoption Path).** Original ranking put scheduling first; that assumed org-wide rollout, which isn't available to a solo, unsanctioned pilot. Gio confirmed the revision: refocus v1 on what's fully within his own control.

### V1 — Gio's own classes only, by July 31
1. **Session record: attendance + video upload/preview** (Google Drive-backed storage, in-app preview)
2. **Credit/progress ledger** — replacing Excel + OClass credit check, for Gio's own students
3. **Scheduling calendar (Gio's own classes only)** — a calendar for the sessions Gio personally teaches. NOT a replacement for OClass's academy-wide scheduling — that stays V2, since it isn't Gio's call to make alone. This version needs no one else's sign-off.
4. **Auto-generated final report** — per-teacher, AI-assisted (teacher writes rough notes → AI drafts polished report text), laid into a PDF template designed via Claude Design. Template *editing UI* is likely P2/out-of-scope for v1 — Gio can edit the template directly as the builder; a self-service editor is not a v1 requirement.

### V2 — after owner/center-manager buy-in
5. **Academy-wide scheduling/booking** — replaces OClass scheduling for every teacher and center. Requires owner sign-off since it affects the whole org and likely means canceling a paid subscription.
6. Org-wide rollout of session records + credit ledger to other teachers/centers

## User Personas *(drafted from context — confirm or correct in PRD phase)*

### Persona 1 — Teacher (robotics/coding instructor)
- **Goal:** Finish class, log attendance, upload session video, note progress — fast, from a phone
- **Frustration:** Currently has to remember a separate Telegram upload step nobody enforces
- **Key scenario:** Class ends → opens KOMS on phone → marks attendance → uploads video → logs credit progress → done

### Persona 2 — Center Manager
- **Goal:** Real-time status across all sessions at their center; produce a trustworthy record when a parent disputes something
- **Frustration:** Currently manually downloads from Telegram and forwards to parents, and cross-checks Excel against OClass when numbers don't match
- **Key scenario:** Parent complains kid was marked absent → manager opens KOMS → sees one record with attendance + video + credit history, resolves it in one lookup

### Persona 3 — Gio (Teacher + Builder, v1's only staff user)
- **Goal:** Run his own classes through KOMS end-to-end without needing anyone else's permission, then have something working to show the owner
- **Frustration:** No org-wide dashboard exists today — but that's a v2 problem, not v1's
- **Key scenario:** Uses KOMS daily as Persona 1 (Teacher). Cross-center/owner visibility is deferred until after buy-in — not a v1 screen requirement.

*(Center Manager persona remains relevant for schema/role design — RLS roles should exist for teacher/center_manager/admin from day one, per the TCS Coffee pattern — but no Center Manager screens are required for v1, since Gio is the only active staff user.)*

### Persona 4 — Parent
- **Goal:** Log into their own account and see their child's progress directly — courses taken, credits left, session videos, reports — without waiting on a manual WhatsApp forward
- **Frustration:** Currently has zero visibility except whatever gets manually relayed, and no way to independently verify a disputed attendance/credit record
- **Key scenario:** Gets an invite when Gio adds their child as a student → logs in via magic link (no password to manage) → sees a read-only progress page for their kid
